# BD Star Transport Divi 5 Changelog

This file records the Divi 5 layout work completed in the working set. The
top-level `bdstar-*-v5.json` files are the import files. The modular source
files under `Modules/` are the editable source of truth used to rebuild them.

## Import and build workflow

1. Edit the relevant `.divi` module source under `Modules/`.
2. Compile the page with `python3 tools/divi_modules.py compile --page <page>`.
3. Validate with `python3 tools/divi_modules.py validate --page <page>`.
4. Import the resulting top-level `bdstar-<page>-v5.json` file in Divi 5.

The Contact hero flow is generated by `tools/enable_contact_hero_form_flow.py`.
When changing that generator, rebuild the Contact source, compile it, validate
it, and copy the compiled result to `bdstar-contact-v5.json` before importing.

## 2026-10-06 — Live SSH deploy tooling (BD Star Transport only)

Added `tools/deploy.sh`, which pushes a compiled `bdstar-<page>-v5.json`
directly to the live site via SSH + WP-CLI (`wp post update`, content read
from STDIN), as an alternative to the manual Divi Portability import dialog.

**Scope is strict and non-transferable: this targets the BD Star Transport
site only.** The SSH host (`159.223.143.61`) is a shared Cloudways server
hosting 30+ unrelated client applications under the same master credential.
`deploy.sh` is hardcoded to BD Star's app path
(`.../868870.cloudwaysapps.com/vywvhnfqke/public_html`) and its page→post-ID
map (home=2, about=38, services=41, contact=45). Do not repoint this script,
its SSH key, or its path/ID mapping at any other client site — see the
"Live deploy via SSH" section in `AGENTS.md` for the full guardrail. Also
recorded in the agency `site-registry` skill (`~/.hermes/skills/agency/
site-registry/references/sites.md`) so other agents/sessions see it too.

Also discovered and documented: the `layout_id` embedded in our exported
`bdstar-*-v5.json` files is unreliable as a post-ID reference — `home`,
`about`, and `services` all carry a stale `layout_id` of `2` internally.
Divi's manual import dialog ignores this field (you pick the target page
in the UI), which is why it never caused a problem before automation.
Real post IDs were confirmed directly via `wp post list` instead.

Header/Footer (Theme Builder templates) are not yet wired into `deploy.sh` —
8 generically-titled `et_template` posts exist on the site and the active
one has not been identified yet. Do not guess; confirm with the operator
first.
